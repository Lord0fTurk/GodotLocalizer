# Changelog

All notable changes to the **GodotLocalizer** project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

---

## [0.1.0] - 2026-10-31

First public pre-release (beta). Tested on Godot 3.6, 4.4, 4.5, 4.6 and 4.7 and on real exported Godot 4.6 games; Godot 4.0–4.3, macOS and Android packages are not verified yet.

### Changed
- **Version reset to `0.1.0`:** The project has not been released yet, so the version moved from `1.0.0-dev` to the pre-release `0.1.0` (`src/version.py`, `Main.qml` fallback label). `1.0.0` is reserved for the first stable release.

### Added
- **Linux/BSD exports:** a PCK embedded in an ELF section (Godot 4.3+ "Embed PCK", 32/64-bit, either endianness) is read like the Windows PE section, ELF binaries (`Game.x86_64`, `Game.arm64`, `Game`) are considered when a folder has no loose `.pck`, and the launch button starts `Game.x86_64` / `.sh` launchers (it reports a missing executable bit instead of failing silently). File URLs keep their leading slash on POSIX. macOS `.app` bundles are not supported yet.
- **Custom-engine exports are named, not hidden:** a package whose signature is not `GDPC` (found in a game that ships `KCVK` plus an encrypted directory) now fails with a message that says so, instead of "No Godot .pck or exe with an embedded PCK found". Such games need the signature and the key from the custom build and are not supported.
- **Clearer, localized problems:** a game that cannot be opened (custom-signature export, folder without a Godot package) now opens a dialog in the UI language that says what happened, why and that nothing was changed, instead of a raw English exception line behind the localized "Error:" prefix. Notifications now stay as long as the text needs (about 4 s plus 45 ms per character, longer for warnings and errors), pause while the pointer is over them, stand out for errors and warnings (tinted card, bold edge, larger icon) and a routine message no longer pushes an unread problem away.
- **Release builds:** `build.py` (PyInstaller, runs the frozen `--self-check`) and `.github/workflows/release.yml` build a Windows zip and an experimental Linux tar.gz on every `v*` tag after lint, tests and an offscreen start-up smoke test; the tag must match `src/version.py`.
- **Tests for the UI translations:** every language must have the same keys and placeholders as English and no Unity leftovers.
- **External language packs (`src/core/langpack.py`):** games that keep their text in `external/data/**.json` and load `external/mods/lang_<code>/` packs by the language chosen in their own menu (found in Futa Succubus Slay: the `.pck` held only a fraction of the text and the game reset the engine locale from its saved settings) are now detected automatically. The pack format is learned from the game's own official packs (which properties a pack carries, which JSON keys hold text), the data is translated with the usual Syntax Guard checks (`[damage]`, BBCode ...) and a new `lang_<code>` pack is written next to them, including `ui_strings.json` and `mod_info.json`. The new language then appears in the game's language menu. Official packs are never overwritten; revert removes only packs written by this tool; review edits rebuild the pack. Games without any official pack are not supported by this route.
- **Syntax Guard protects game variables:** lowercase `[damage]`, `[player_name]`-style placeholders are kept untouched during translation (BBCode tags like `[color=…]` stay handled separately). In the sample games this covers dozens of strings that would otherwise have been mangled.
- **Completion dialog:** the result card no longer overflows (content now fits with real padding, buttons wrap), and it explains why some lines were not translated (rejected by the format check / failed / unchanged). A QML smoke check guards against the overflow returning.
- **Binary resource support (`src/core/binary/`, `src/harvesters/binary_harvester.py`):** reader for Godot's `RSRC` container (Godot 3 and 4 headers, all variant types), text harvesting from exported binary scenes (`.scn`, node-aware via the packed `_bundled` layout) and `.res` resources, `.translation` tables (plain `Translation` keeps its keys) and `OptimizedTranslation` (smaz-compressed, hashed keys): values are harvested, translated and shipped as a rebuilt table with the original hash slots, which the bootstrap re-creates at runtime — no source keys required. Exported games that only contain binary scenes now yield text instead of nothing.
- **Fonts & RTL:** the custom font from Settings now actually ships in the patch (previously `font_bytes` was never passed) and is coverage-checked against the target language, with glyph charsets for pt/it/pl/uk/ar/fa/he/ja/zh/ko added. The Godot 4 bootstrap builds the font from its raw bytes (a raw `.ttf` in a pack has no `.import`, so `load()` could never work) and adds it as a fallback correctly; Godot 3 gets `DynamicFont` fallback support too. RTL text is pre-shaped only for Godot 3 — Godot 4's text server shapes Arabic/Hebrew itself.
- `GodotTranslationPipeline.run()` was split into harvest/translate/apply/deploy phases, with offline end-to-end phase tests.
- **Harvester quality:** GDScript harvesting no longer treats `#` inside strings as a comment, understands single-quoted strings and skips identifier/engine-call literals (and `.gd` sources now join the pipeline through the runtime table); `.tscn` values spanning several lines and `popup/item_N/text` / `tab_N/title` properties are handled; PO parsing supports `msgctxt`, plurals, fuzzy flags and continuation lines; Dialogue Manager logic lines (`if`, `do`, `set`, `=>`) are no longer mistaken for dialogue, `[ID:…]` tags, `(mood)` modifiers and trailing comments survive rewriting, and `{{variable}}` expressions are protected as a unit.
- **Project hygiene:** `pyproject.toml` now carries real package metadata with the version read from `src/version.py` (single source), GitHub Actions CI runs ruff + pytest on Windows/Linux (Python 3.10 and 3.13), and the AGENTS.md directory map matches the code.
- **Verified against real exported games** (three Godot 4.6.x titles): the binary scene node table uses a 6-integer header with the group count *after* the properties (the first implementation guessed wrong and its self-made fixtures hid it), and compressed `RSCC` resources (zstd/deflate/gzip blocks, offsets relative to the decompressed stream) are now read. All ~1,500 scenes/resources in the samples parse without errors and yield real UI text.
- **Verified against the real engine (Godot 4.7.2 and 3.6.3, headless):** a test project is exported to a PCK, patched by the real pipeline phases and run again. It found and fixed three bugs that spec-built fixtures could not: `PCKWriter` stored unpadded path lengths (Godot reads the stored length literally, so the whole directory was misread and the patch silently contributed nothing), the Godot 3 hashed-translation class is called `PHashTranslation` (the Godot 3 bootstrap failed to parse), and the font fallback replaced the engine's default font instead of extending it. Confirmed on 4.7.2/3.6.3: translated scene text, key lookups through rebuilt `OptimizedTranslation` tables (including `%d` formats), locale switching, `[autoload_prepend]` ordering (Godot 4 only; Godot 3.6 ignores it), font fallbacks and clean revert. `tests/test_godot_engine.py` repeats this when `GODOT4_BIN` / `GODOT3_BIN` point at an editor build.
- `Translation.locale` is omitted from files when it equals the default (`en`), so English tables carry no locale property; a missing locale now means `en`, and Godot 4.6/4.7 `PACK_FORMAT_VERSION` 4 packs are read.
- **Optional GDRE Tools backend (`src/core/external/gdre.py`):** with a `gdre_tools` executable configured in Settings (or `GDRE_TOOLS` / `PATH`), compiled `.gdc` scripts are decompiled headless (`--recover --scripts-only`, key passed for encrypted packs) and their strings join the runtime translation table. Plugin code under `res://addons/` and developer log strings (`print`, `INFO:`/`ERROR:` …) are skipped. Verified with GDRE Tools v2.7.4 on a Godot 4.7.2 test pack and a real 4.6 game (223 scripts in ~5 s). GDRE is never bundled or downloaded by the app.
- **Custom JSON schemas & script noise:** Settings has a field for extra JSON key names that hold player-facing text (e.g. `card_description`), used for harvesting and rewriting; `res://saves/` files are ignored. Script harvesting drops developer log strings (`_log(...)`, lowercase prose without capitals, `act%d_boss` style identifiers). Measured with GDRE on three real games: compiled scripts add 159–2,500 unique strings per game (FutaSucc: 73 → 483) after filtering.
- **More engine verification:** the patch/translate/revert flow also passes on Godot 4.4.1 (PCK format 2); `[autoload_prepend]` is honoured from Godot 4.6 on (measured on 4.4.1, 4.5.1, 4.6.2, 4.7.2 and 3.6.3: only 4.6.2 and 4.7.2 run the bootstrap first; older engines run it after the game's own autoloads). PCK format 3 is confirmed on 4.5.1/4.6.2, format 4 on 4.7.2, format 2 on 4.4.1. A Godot-4.7.2-exported *encrypted* PCK (format 4, encrypted directory and files) is read and MD5-verified by `PCKReader`, and an encrypted pack rewritten by `RepackPatcher` opens cleanly in GDRE Tools (which uses the engine's own decryption code) and is rejected with the wrong key.
- **Native compiled-script reader (`src/core/binary/gdc.py`):** string literals are read straight from the constant tables of Godot 4.3+ `.gdc` files (`GDSC` tokenizer buffers, zstd payloads, Variant-encoded constants), so GDRE Tools is no longer needed for them. On three real Godot 4.6 games it reads 1,026 of 1,028 scripts (the other two held `NodePath` constants, now supported) and finds everything GDRE's decompiled output yields (0 strings only GDRE found) in 0.2–5 s instead of 6–20 s; without call context it filters by shape (log prefixes, concatenation fragments, file masks). GDRE stays an optional backend, preferred when configured and useful for pre-4.3 bytecode.
- **Consent-based GDRE Tools download (`gdre_download.py`, Settings → GDRE Tools → Download):** the app looks up the newest stable GDRE release (metadata only), shows file name, size, source page, SHA-256 and license in a confirmation dialog, and only after the user presses *Download* fetches it. The download must come from GitHub hosts (redirects included), match the digest GitHub publishes (refused when absent), stay within the announced size and is unpacked with zip-slip protection into the app's own data folder; the executable path is stored in the settings automatically. Covered by offline installer tests and a headless QML test that loads the real settings view and opens the dialog.
- **Credentials in the OS credential store (`src/utils/config.py`):** with the optional `keyring` package, API keys and the PCK encryption key are kept in Windows Credential Manager / Keychain / Secret Service and written as empty strings to `config.json`; plaintext values from older files are migrated on the next start, a failing store falls back to the file instead of losing the key, and portable mode or `GODOTLOCALIZER_NO_KEYRING=1` keeps the old behaviour. Verified with a fake store and a real Windows Credential Manager round trip.
- **Pre-flight analysis instead of up-front settings:** pressing Translate now inspects the package first and asks only what is actually needed — a dialog for the encryption key when the game is encrypted (or the key is wrong/invalid), a checklist of JSON fields that look like player text with sample values (`src/core/pipeline/analysis.py`; columns that usually hold a translation, such as `target`, are never pre-ticked), and an offer to download GDRE Tools only when scripts in a pre-4.3 bytecode format are present. Answers are remembered (the chosen JSON fields go into the settings); the Settings cards stay as a manual override. Measured on three real games: FutaSucc and Feral Bay produce a JSON question, Futoria starts straight away. Covered by backend-flow tests and a headless QML test that opens all three dialogs.
- **Shareable patch packages (`src/patcher/package.py`):** the dashboard's export button was a stub that only showed a message; it now zips the deployed patch (never game files) with install/uninstall scripts for Windows (`.bat`) and Linux/Steam Deck (`.sh`) and a bilingual README, and a new *Install a patch package…* button installs such a zip safely (existing `override.cfg` settings are merged, zip-slip rejected, a warning is logged when the game version differs). A small sidecar (`godotlocalizer_patch.json`) records language, tool version and a fingerprint of the game package, so the dashboard shows *Patched · tr* or *The game was updated; rebuild the patch*. Verified by running the generated `install.bat`/`uninstall.bat` on Windows and by exporting a package from a patched test game and installing it into a clean copy on Godot 4.7.2, 4.4.1 and 3.6.3.
- **Editor 'Save to game' now really updates the game:** it only wrote the translation cache while claiming success; it now rebuilds the patch from the reviewed rows without calling a translation engine (`GodotTranslationPipeline.apply_session`).
- **Translation sheets for human translators (`src/core/pipeline/sheet.py`):** export the strings as CSV (UTF-8 with BOM so Excel reads umlauts and Turkish letters correctly, formula-safe cells) and import the filled sheet back (`;`/tab/`,` detected automatically, rows matched by source text, Syntax Guard still applies, empty cells never wipe existing text). Buttons in the editor.
- **Clear message when nothing is found:** a package without translatable text now explains it instead of finishing silently.
- Tests: `tests/conftest.py` makes temp-directory cleanup tolerant (Windows scanners could randomly lock files and fail unrelated tests).
- **Command-line mode (`src/cli.py`, `run.py <command>`):** `inspect`, `translate`, `status`, `export`, `install` and `revert` run the same pipeline without the GUI (exit codes: 0 ok, 1 error, 2 usage, 3 nothing to translate, 4 key needed). The README now describes the five typical usage scenarios (play, human-reviewed translation, sharing, game updates, batch use).
- **Bilingual display that cannot break the game (`src/core/bilingual.py`):** the `bilingual_mode` setting existed only as a config key with no effect. It now has a switch and template field in Settings and appends the original text below the translation only for plain text; strings with format specifiers (`%d`, `%05d`), variables (`{name}`, `{{expr}}`) or markup tags stay single-language, and right-to-left targets are never mixed. Verified on Godot 4.7.2, 4.4.1 and 3.6.3 with `tr("…") % value` formatting.
- **Settings cleanup:** the Unity-only TextMeshPro/uGUI font card was replaced by the bilingual card; the 'automatic .bak backup' claim (never true for this app) now says that game files are never modified; the GDRE card no longer says the app never downloads it.
- **Upgrade from the first versions:** folders patched by the pre-0.1 tool (`patch.pck` + `patch_bootstrap.gd`) are recognised by the old bootstrap's own marker, replaced on the next deployment and removed by *Remove patch*; a game's own `patch.pck` is never touched.
- **Settings: one collapsed 'Advanced' card:** the encryption-key, extra-JSON-fields and GDRE Tools fields no longer sit open in the settings; they are asked for during translation when actually needed and live in a single card (hidden by default) for changing or clearing a saved value. The bilingual template is edited as `{target}
({source})` (typed `
` = line break) because a real line break is invisible in a one-line field.
- **The JSON question is now the app's job, not the user's:** fields are classified instead of listed. Sentence fields are added automatically (and logged); two parallel columns such as `source`/`target` are recognised as the game's own localization table — the English column is taken as the text to translate and the other as an existing translation to leave out; names, placeholders and ids are ignored. A dialog appears only for genuinely unclear cases (short phrases, or two columns whose original language cannot be told), and each row explains in plain language what it probably is and shows an example, with the recommendation pre-ticked. Measured on the three sample games: FutaSucc resolves itself (`source` in, `target` out), Feral Bay adds its character notes, Futoria asks nothing.
- **Encrypted PCK support (`src/core/pck/crypto.py`):** AES-256-CFB decryption of Godot's encrypted pack directory and per-file payloads (`md5 | length | iv | ciphertext` blocks), with the 64-character hex key entered under Settings → Encrypted PCK. A missing or wrong key now fails with a clear message instead of garbage data. `PCKWriter`/`RepackPatcher` can write encrypted directories and files, so a repacked encrypted game keeps its encryption. Keys are masked in logs.

### Fixed
- **Dialogic 2 narration was never translated:** timelines were only read for `Speaker: text` lines. Speaker-less narration, `????:` speakers, `{Name} ...` lines and text starting with BBCode are now harvested and written back (Mystic Lust: 5,834 -> 6,394 lines); commands, `[shortcode]` events, `#id:` markers and comments stay untouched.
- **Placeholders mangled by engines:** Dialogic inline effects (`[pause=0.5s]`, `[speed]`, `[signal]`, `[portrait]`, `[mood]`, `[nl]`, `[br]`) are protected, as are subscripted variables (`{Save.dict["a"]["b"]}`). Renamed, bracket-stripped, half-dropped or HTML-escaped `⟦ULPH_n⟧` sentinels are restored by index, and an unrecoverable leftover is rejected instead of being "repaired" around. Cached translations that fail the integrity check are translated again.
- **CJK targets (ported from UnityLocalizer):** engines that swap the placeholder brackets for `「」`, `［］`, `【】` or `（）` or use a fullwidth underscore no longer leave stray brackets around restored variables; `[name=value]` directives (`[wait=0.5]`, `[pic=39]`) are protected; protected names and glossary terms are found next to kana and Han ("Aliceは").
- **Google on a throttled IP:** separator batches no longer sleep out the shared 429 cooldown when `batchexecute` can answer (120 lines: 80 s -> 8 s).
- **UI:** clipped labels on Toolbox tags and secondary buttons, a dead "patch loose files" option (it did nothing and contradicted the non-destructive philosophy) and a translation-memory button that did not add the file were fixed; Unity-era strings were removed or translated in all 12 languages; the diagnostics card is hidden until a game is selected.
- **Overlay patch safety (`src/patcher/`):** `override.cfg` is now merged line-ending agnostically (CRLF no longer drops the autoload) and only the `GodotLocalizerBootstrap` entry is added/removed, so a game's own `override.cfg` survives Clean Revert. The bootstrap is also listed under `[autoload_prepend]` so supporting engines start it before the game's autoloads. Output files are namespaced (`godotlocalizer_patch.pck`, `godotlocalizer_bootstrap.gd`) so a game's own `patch.pck` is never overwritten or deleted; failed deployments roll back, and `PCKWriter` removes its `.tmp` file on errors.
- **Translations now reach the game (`bootstrap_script.py`, `pipeline/harvest.py`):** the patch ships a `translations.json` that the bootstrap registers with `TranslationServer`, keyed by original text (and by CSV translation keys), so hardcoded UI text localizes even inside binary scenes. Locale codes are normalized to Godot form (`pt-BR` → `pt_BR`).
- **Write-back for more formats:** `.tscn`, Dialogic 2 `.dtl` and Dialogic 1 timeline JSON are rebuilt after translation; Dialogue Manager rebuild keeps CRLF and the trailing newline. CSV/PO are intentionally not rewritten (Godot only reads their imported `.translation` output).
- **Pipeline performance & discovery:** only text-bearing extensions are read from the pack (no more loading textures/audio into memory), translation-key strings (`UI_START_GAME`) are skipped, game folders ignore our own output and helper executables, and PCKs embedded in a PE `pck` section (Godot 4.3+ "Embed PCK") are detected. `read_file_bytes(verify_md5=True)` and extraction discard corrupt data.
- **Syntax Guard:** protects Godot RichTextLabel BBCode (`[color=…]`, `[center]`, `[wave amp=…]`, …) and `String.format`/printf specifiers (`%05d`, `%+d`, `%%`); glyph checks raise for languages without a charset instead of silently using Turkish.
- Removed the unused `pefile` dependency and the machine-specific `file:///D:/…` links in the README.
- **PCK format flags (`src/core/pck/`):** Pack flag constants now match Godot (`DIR_ENCRYPTED=1`, `REL_FILEBASE=2`; added `SPARSE_BUNDLE`, file `REMOVAL`/`DELTA`). `PCKWriter` no longer marks Godot 4.0–4.4 patch directories as encrypted, `PCKReader` applies `file_base` per the engine's rules, ignores removed entries, and rejects encrypted/sparse packs with a clear error instead of misparsing. The overlay patcher now receives the game's real engine version. Added spec-based byte-level tests (`tests/test_pck_format.py`).
- **Google Rate-Limit Parity with RenLocalizer (`src/core/translators/`, `src/core/pipeline/orchestrator.py`):** Closed the gaps that caused premature Google 429 / limit warnings:
  - Duplicate strings are now deduplicated at both manager and Google-engine level (RenLocalizer parity): repeated game lines are translated once and fanned out, sharply reducing request volume.
  - HTTP 200 replies with empty payloads are now treated as Google's soft-ban signal (mirror failure + family fallback) instead of being accepted as successful empty translations.
  - The UI `batch_size` setting (default 100) is now actually wired into the pipeline runner; previously every run silently used 25 lines per batch, quadrupling request count.
  - Cooldown sleeps carry random jitter so parallel workers no longer resume in lockstep after a 429 cooldown.
  - Separator batch character budget now follows the user's `max_chars_per_request` setting (hard cap 8000), matching RenLocalizer's slice tuning.
- **Pipeline & Glossary Integration (`src/core/pipeline/orchestrator.py`):** Fixed missing `glossary` and `cache` property delegates on `GodotTranslationPipeline` referenced by `AppBackend`, resolving `AttributeError: 'GodotTranslationPipeline' object has no attribute 'glossary'`.
- **Review Session Persistence (`src/core/pipeline/review_session.py`):** Added `shippable_count` property and `save_review` pipeline bridge ensuring manual edits from Review Editor correctly persist to cache and game patch files.
- **Cache Clearing Counter (`src/core/cache.py`):** Updated `TranslationCache.clear()` to return deleted records count.

### Added
- **Proxy-Adaptive Concurrency (`src/core/translators/network.py`):** `ProxyPool.adaptive_concurrency()` ports RenLocalizer's field-tuned tier table (5+ healthy proxies → 4x parallelism, 50+ → 32x); without proxies the single-IP safety cap of 4 remains.
- **Alternate-Family Rescue Reporting (`src/core/translators/google.py`):** Periodic status warning while primary Google endpoints are IP-blocked and alternate families (batchexecute/clients5/Lingva) are carrying traffic.
- **Translator Rate-Limit Test Suite (`tests/test_translators.py`):** 13 tests covering dedup fan-out, soft-ban fallback, adaptive concurrency tiers, circuit-breaker probe gating, cooldown jitter, and batch-size wiring.
- **Full Autonomous Translation Engine Suite (`src/core/translators/`):** Ported battle-tested translation engines from RenLocalizer / UnityLocalizer, supporting Google Translate (multi-endpoint, batchexecute, fallback mirrors), Bing Edge Translator, DeepL Pro/Free, Google Gemini 2.0, OpenAI GPT-4o, DeepSeek V3/R1, Local LLM (Ollama / LM Studio), and LibreTranslate.
- **Godot Translation Pipeline Orchestrator (`src/core/pipeline/`):** Complete automated workflow for game profiling, multi-threaded batch translation runner, persistent review sessions, and zero-touch patch deployment.
- **Interactive Review Editor (`src/backend/editor_backend.py`, `EditorView.qml`):** Post-run translation validation and review UI with Syntax Guard problem filtering (rejected, invalid, failed, edited, repaired, accepted), real-time search, and manual patch override saving.
- **Godot Toolbox & Typography Doctor (`ToolboxView.qml`, `src/backend/app_backend.py`):**
  - Godot Font & Tofu Doctor CMAP glyph coverage scanner for Turkish, Cyrillic, CJK, and Arabic charsets.
  - PCK Dissector & Unpacker extracting standalone `.pck` or embedded Windows `.exe` packages into clean `res://` directory trees.
  - One-click Clean Revert restoring untouched vanilla state by safely unlinking `patch.pck`, `override.cfg`, and autoload scripts.
- **Persistent SQLite Translation Cache & Glossary Manager (`src/core/cache.py`, `src/core/glossary.py`):** Thread-safe SQLite caching to prevent duplicate API requests and custom terminology protection during translation.
- **Syntax Guard & RTL Shaper (`src/core/syntax_guard.py`, `src/core/rtl_shaper.py`):** Comprehensive BBCode, Godot format specifiers (`%s`, `%d`), and bidirectional Arabic/Hebrew text shaping.
- **Vector Icons Font Suite (`src/gui/qml/fonts/`):** Bundled `RenLocalizerIcons.ttf` with Lucide icon mapping components (`Icon.qml`, `IconLabel.qml`, `Icons.qml`).
- **Complete Desktop GUI (`run.py`, `src/gui/`):** Built with PyQt6 and QML adhering strictly to `DESIGN.md` (Obsidian, Daylight, and Cyber Neon 3-theme matrix with Preset B Emerald tokens).
- **Multi-language UI Engine (`src/gui/i18n/`):** Dynamic runtime translation switching across 12 languages (`tr`, `en`, `de`, `fr`, `es`, `ru`, `pt-BR`, `ja`, `zh-CN`, `ko`, `it`, `fa`).
- QML Components Suite: `PrimaryButton`, `SecondaryButton`, `SectionCard`, `StatusBadge`, and responsive views (`DashboardView`, `HarvesterView`, `PatcherView`, `SettingsView`).
- Non-destructive Patching Engine (`src/patcher/`): Method A (PCK Overlay + `override.cfg` + `patch_bootstrap.gd`) and Method B (Full PCK Repacker).
- Typography & Glyph Doctor Engine (`src/core/font_engine/`): TrueType/OpenType Unicode CMAP analyzer preventing missing character (tofu / `□`) errors.
- Multi-channel Narrative & Scene Harvesters (`src/harvesters/`, `src/parsers/`): Support for Nathan Hoad's Dialogue Manager (`.dialogue`), Dialogic 1.x & 2.x (`.dtl`, `.json`), Godot scenes (`.tscn`), and Gettext PO/CSV catalogs.
- Pure-Python PCK binary engine supporting Godot 3.x (Format 1) and Godot 4.x (Format 2) PCK archives (`src/core/pck/`).
- Automated 12-byte trailer parser for self-contained Godot Windows PE executables (`Oyun.exe`).
- End-to-End integration test suite (`tests/test_integration.py`) verifying full game disassembly, string harvesting, translation substitution, and overlay patching.
